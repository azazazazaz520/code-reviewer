# 用户界面文案边界

## 目的

用户界面只描述用户可以理解并可以操作的能力，不展示研发阶段、实现计划、内部优先级或暂未开放的接口安排。

## 规则

1. 页面文案不得出现 `P0`、`P1`、`只读阶段`、`后续阶段`、`不提供入口`、`当前后端进程`、`待实现` 等研发语汇。
2. 设置页只展示已经接入真实消费者的配置。可编辑字段必须同时具备：保存接口、字段校验、生效时机和回归测试。
3. 能力受运行环境限制时，说明用户可以采取的动作，例如“当前运行环境不支持直接管理密钥，请通过运行环境配置提供”，不得解释内部迭代计划。
4. 后端响应模型只返回用户需要的状态和操作结果；模块名、内部错误栈、部署参数和开发备注不得进入响应文案。
5. 新增设置分区时，必须同时补充用户可见文案、保存失败反馈、版本冲突处理和前端文案回归测试。

## 自动检查

`frontend/src/pages/Settings.test.tsx` 会遍历设置分区，检查页面不出现研发阶段和实现限制词汇。后续如果新增设置页面或公共文案，应将相同检查扩展到对应页面测试。

代码评审还需确认：

- 页面描述的是“能做什么”和“何时生效”，而不是“当前版本没做什么”；
- 敏感值只显示状态，保存和清除经过受限桌面桥接；
- 诊断信息与用户提示分离，用户提示不直接复述内部异常。
